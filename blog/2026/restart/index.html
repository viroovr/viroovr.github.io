블로그를 다시 시작하며

November 6, 2026

2026   ·   retrospective     ·   blog  

이 블로그는 학부생 때 만들어 두고 2년 가까이 멈춰 있었습니다. 지금은 협업툴 Flow 에서 백엔드 개발자로 일하고 있고, 그 사이 기록하고 싶은 일이 많이 쌓여서 다시 열었습니다.

앞으로 쓸 것

트러블슈팅 기록. 운영에서 “느리다”, “CPU 가 높다”, “가끔 데이터가 이상하다” 같은 보고를 받으면, 저는 아래 순서로 정리합니다.

  1. 증상 — 사용자가 본 것
  2. 관측 사실 — 로그, 메트릭, 프로파일 결과처럼 확인된 것
  3. 원인 후보 — 최대 3개, 각각 근거와 함께
  4. 수정 — 고른 방법과 고르지 않은 방법, 그리고 이유
  5. 검증 — 원래 재현 케이스를 다시 돌려 숫자로 확인

이 블로그의 글도 같은 틀을 따르려 합니다. 회사 내부 정보는 빼고, 기술적으로 배운 점 위주로 씁니다.

사이드 프로젝트. 개인 투자 대시보드, LLM 으로 만든 자소서 검토 도구처럼 직접 쓰려고 만든 것들의 설계와 시행착오를 남깁니다.

왜 다시 쓰나

문제를 끝까지 추적하고 나면 그때는 다 아는 것 같지만, 몇 달 뒤 비슷한 문제를 만나면 처음부터 다시 헤맵니다. 그래서 다음에 더 빨리 푸는 방법까지 적어 두는 것이 목표입니다.
